# BNI 맥스 현장 출석 체크인 — 설계서

호텔 정기모임장에 도착해야만 출석이 기록되는 시스템의 설계다.
멤버는 **호텔 데스크의 NFC 태그에 폰을 대거나 QR을 찍는 것으로 끝난다.** 앱 설치·로그인 없다.

---

## 1. 설계의 핵심 문제

NFC 태그도 QR도 **"이 사람이 누구인지"는 증명하지 못한다.** 증명하는 것은 "이 폰이 지금 이 태그에 닿았다"는 사실뿐이다.
반대로 이름 선택 방식은 "누구인지"는 알지만 "어디에 있는지"를 모른다.

그래서 두 가지를 곱한다.

```
장소 증명   태그/QR 을 물리적으로 탭 → 호텔 데스크에 있었다
    ×
사람 증명   폰에 저장된 기기 토큰   → 그 폰의 주인이 누구인지 안다
    =
출석 인정
```

기기 토큰은 **최초 1회만** 등록한다. 그 뒤로는 탭 한 번에 이름 입력조차 없이 체크인이 끝난다.

---

## 2. 멤버가 겪는 흐름

### 최초 1회 (첫 모임, 약 20초)

```
데스크 태그에 폰을 댐
   → 브라우저가 자동으로 열림
   → "누구세요?" 이름 카드 그리드 (파워팀별 색상)
   → 본인 이름 탭
   → "김OO 님, 이 폰을 등록했습니다. 다음부터는 대기만 하면 됩니다"
   → 체크인 완료 ✓  06:52  출석(P)
```

### 두 번째 모임부터 (약 3초)

```
데스크 태그에 폰을 댐
   → 브라우저 열림 → 즉시 "김OO 님 체크인 ✓ 06:51 출석"
   (탭할 것도, 고를 것도 없다)
```

### 이미 체크인한 뒤 또 탭하면

```
"이미 체크인되어 있습니다 (06:51 출석)"   ← 기록은 바뀌지 않음
```

## 3. 물리 설치

| 위치 | 매체 | 개수 | 비고 |
|---|---|---|---|
| 호텔 연회장 입구 | NFC 태그 + QR 병기 아크릴 스탠드 | 1 | 주 동선 |
| 등록 데스크 | NFC 태그 + QR 병기 테이블 텐트 | 1 | 대기 줄 분산 |
| 예비 | 인쇄 QR 카드 | 2 | 태그 분실·손상 대비 |

**실무 주의점**

- 금속 테이블 위에 NFC 태그를 직접 붙이면 인식되지 않는다. **on-metal(페라이트 시트 내장) 태그**를 쓰거나 아크릴 스탠드에 띄워 붙인다.
- 태그는 반드시 **QR과 나란히** 배치한다. NFC 미지원·미숙 멤버가 즉시 대체 수단을 쓸 수 있어야 줄이 막히지 않는다.
- 안내 문구는 한 줄로: **"폰 뒷면을 여기에 대세요 · 안 되면 QR"**

**기기별 동작**

| 기기 | NFC 동작 | 대응 |
|---|---|---|
| iPhone XS 이상 | 잠금화면에서도 태그 감지 → 상단 배너 → 탭하면 Safari | 정상 |
| iPhone 7~X | 백그라운드 감지 제한 → 제어센터의 NFC 리더 필요 | QR 안내 |
| Android (NFC 켜짐) | 태그 대면 브라우저 자동 실행 | 정상 |
| Android (NFC 꺼짐) | 반응 없음 | QR 안내 |

→ **NFC는 주 수단, QR은 동등한 대체 수단**으로 설계한다. NFC 전용으로 가면 현장에서 반드시 사고가 난다.

## 4. 대리 체크인 방지 — 태그 등급 3단계

정적 URL을 담은 일반 태그·QR은 **링크를 복사해 단톡방에 뿌리면 집에서도 체크인된다.** 이걸 어디까지 막을지 정하는 문제다.

### 티어 1 — 정적 URL (NTAG213 일반 / 인쇄 QR)

- 단가: 태그 300원 / QR 인쇄 0원
- URL: `…/checkin?tag=A`
- 방어: 체크인 시간창(06:20~07:40) + 모임일만 허용 + 1일 1회
- 한계: **링크 공유로 원격 체크인 가능**

### 티어 2 — NFC 카운터 미러 (NTAG213/215) ← 권장

- 단가: 태그 500원 내외
- 태그가 **탭될 때마다 내장 카운터를 1 증가시켜 URL에 자동으로 넣어 보낸다**
  `…/checkin?tag=A&ctr=00019A`
- 서버는 `ctr`이 마지막으로 본 값보다 커야만 인정 → **이미 쓰인 링크를 복사해 보내면 거부된다**
- 한계: 카운터에 암호 서명이 없어, 숫자를 손으로 키워 넣는 의도적 위조는 이론상 가능
- 판단: 40명 규모 신뢰 조직에서 **무심코 링크를 공유하는 경로는 완전히 차단**된다. 실용적 최적점.

### 티어 3 — NTAG 424 DNA (SUN 인증)

- 단가: 태그 2,000~4,000원
- 태그가 탭마다 **UID·카운터를 AES로 암호화하고 CMAC 서명**을 붙여 URL을 매번 새로 만든다
  `…/checkin?picc_data=<암호문>&cmac=<서명>`
- 서버가 AES 키로 검증 → **복제·위조 암호학적으로 불가**
- 비용: 백엔드에 AES-128 구현이 필요하다. Apps Script는 AES 내장 함수가 없어 경량 AES 라이브러리를 넣거나, 검증만 Cloudflare Workers(무료)로 빼야 한다.

> **권고: 티어 2로 시작한다.** 실제 부정 체크인이 관찰되면 그때 태그만 424 DNA로 교체하면 된다. URL 구조와 서버 검증 단계만 바뀌고 나머지 설계는 그대로다.

### GPS는 넣지 않는다

NFC 탭이 이미 물리적 현장 증명이다. 여기에 위치 권한 팝업까지 얹으면 마찰만 늘고 이탈이 생긴다. QR 경로에만 선택적으로 켤 수 있게 설정 항목으로 남겨둔다.

## 5. 시스템 구조

```
   [ 호텔 데스크 ]
   NFC 태그 (NTAG213, 카운터 미러)
   QR (동일 URL, tag=QR)
            │  탭 / 스캔
            ▼
   https://jwchoi061217-web.github.io/-/bni/checkin/?tag=A&ctr=00019A
   ── GitHub Pages 정적 페이지 ─────────────────────────
     · 기기 토큰(localStorage) 확인
     · 없으면 이름 선택 화면
     · 있으면 즉시 전송
            │  POST (기기토큰 + tag + ctr)
            ▼
   Google Apps Script 웹앱  ── 검증 계층 ─────────────
     ① 오늘이 모임일인가
     ② 지금이 체크인 창(06:20~07:40) 안인가
     ③ tag 가 등록된 태그인가
     ④ ctr 이 마지막 값보다 큰가          ← 링크 재사용 차단
     ⑤ 기기토큰이 등록된 멤버인가
     ⑥ 오늘 이미 체크인했는가            ← 중복 무시
     → 07:00 이전 P / 이후 L 판정 후 기록
            │
            ▼
   Google Sheets (DB)  ─── 서기·임원 권한만 접근
            │
            ├─▶ 현황판 (데스크 노트북/TV, 10초 폴링)
            └─▶ 월간 통계 · 6개월 결석 경고 · BNI Connect CSV
```

서버를 새로 두지 않는다. **GitHub Pages(화면) + Apps Script(로직) + 스프레드시트(DB)** 로 월 비용 0원이며, 이미 이 레포가 쓰는 Pages·Actions·카톡 발송 파이프라인을 그대로 재사용한다.

## 6. 데이터 모델 (구글시트 탭 구성)

**`members`**

| memberId | 이름 | 파워팀 | 업종 | 상태 | 가입일 |
|---|---|---|---|---|---|

**`devices`** — 사람 증명의 근거

| deviceToken (UUID) | memberId | 등록일시 | 최근사용 | 등록방법 |
|---|---|---|---|---|

한 멤버가 폰 2대를 등록할 수 있다. 폰 교체·시크릿모드면 이름 선택 화면이 다시 뜨고 새 토큰이 추가된다. 서기는 관리 화면에서 오래된 토큰을 정리한다.

**`tags`** — 장소 증명의 근거

| tagId | 설치위치 | 종류 | lastCounter | 활성 |
|---|---|---|---|---|

**`checkins`** — 원장(append-only, 수정하지 않는다)

| 타임스탬프 | 날짜 | memberId | 코드 | 방법 | tagId | ctr | 비고 |
|---|---|---|---|---|---|---|---|

방법 = `NFC` / `QR` / `수동`

**`attendance`** — 회차별 최종 출결 (서기가 보정하는 시트)

| 날짜 | memberId | 코드 | 대참자명 | 사유 | 확정자 |
|---|---|---|---|---|---|

코드는 BNI 출결 코드를 그대로 쓴다 — `P` 참석 · `L` 지각 · `A` 무단결석 · `M` 의료·경조 · `S` 대참자 참석.
체크인 기록이 없는 활동 멤버는 모임 종료 시 자동으로 `A`가 되고, 서기가 `M`/`S`로 보정한다.

**`visitors`**

| 날짜 | 이름 | 회사 | 업종 | 초대자 | 연락처 | 동의 |
|---|---|---|---|---|---|---|

## 7. 판정 규칙

| 항목 | 규칙 | 설정 가능 |
|---|---|---|
| 체크인 창 | 모임 시작 40분 전 ~ 40분 후 | ✅ |
| 지각 기준 | 07:00 (모임 시작 시각) | ✅ |
| 중복 탭 | 최초 1건만 기록, 이후 안내만 표시 | — |
| 미체크인 처리 | 모임 종료 시 활동 멤버 자동 `A` | ✅ |
| 모임일 | 요일 지정 + 휴회일 예외 목록 | ✅ |

### 선택: 퇴장 체크아웃

"찍고 나가는" 문제를 막으려면 종료 시각에 두 번째 탭(체크아웃)을 요구할 수 있다.
다만 **초기에는 켜지 않기를 권한다.** 마찰이 두 배가 되고, BNI 모임 특성상 실제 문제가 되는 사례가 적다. 필요해지면 설정으로 켠다.

## 8. 현장 실패 대비 (이게 없으면 첫 주에 사고 난다)

| 상황 | 대비책 |
|---|---|
| 호텔 지하 통신 불량 | 전송 실패 시 브라우저에 큐 저장 후 자동 재시도. 화면엔 "체크인됨(전송 대기)" 표시 |
| 태그 손상·분실 | QR 예비 카드 2장 상비. tagId만 다르고 동작 동일 |
| 폰을 안 가져온 멤버 | 현황판의 **수동 추가** 버튼 → 방법 `수동`으로 기록 (누가 추가했는지 함께 남음) |
| Apps Script 장애 | 현황판에서 명단 인쇄 → 종이 체크 후 서기가 일괄 입력 |
| 오인식·잘못 누름 | 서기 관리 화면에서 당일 기록 수정. 원장은 남고 보정 이력이 추가 기록됨 |

## 10. 구축 순서

각 단계가 끝날 때마다 **그 주 모임에서 바로 쓸 수 있다.**

| 단계 | 내용 | 이 시점에 가능한 것 |
|---|---|---|
| **1주차** | 체크인 페이지 + 이름 선택 + 시트 기록 + 현황판 + 수동 추가 | QR 인쇄물만으로 즉시 운영 시작 |
| **2주차** | 기기 토큰 등록·재사용, 지각 자동 판정, 중복 처리 | 두 번째 모임부터 **무선택 원탭** |
| **3주차** | NFC 태그 발주·설치, 카운터 검증, QR 병행 | 폰 대기만으로 체크인 |
| **4주차** | 월간 통계, 6개월 결석 경고, BNI Connect CSV, 방문자 등록 | 서기 수기 집계 종료 |
| **5주차** | 모임 전날 카톡 자동 안내(기존 발송 파이프라인 재사용) | 완전 자동 |

## 11. 개인정보 처리

- 시트 접근 권한은 **회장·부회장·서기로 제한**한다. 링크 공유 금지.
- 수집 항목은 이름·소속·출결 시각으로 한정한다. **위치정보는 수집하지 않는다.**
- 방문자 연락처는 수집 화면에 동의 체크와 이용 목적을 명시하고, `동의` 컬럼에 기록한다.
- 기기 토큰은 임의 UUID이며 폰의 식별자(IMEI·광고 ID 등)를 쓰지 않는다.
- 탈퇴 멤버의 기기 토큰과 연락처는 정리 주기를 정해 삭제한다.
